# rnfs 0.1.2 proposal

*Status: draft for review · Date: 2026-10-13 · Base: `dev` @ `22688db` · Source: [audit.md](audit.md)*

## Goal

0.1.2 is a **maintenance release**. It fixes what shipped broken in 0.1.1 and adds guardrails so the same problems can't ship again. It also takes the cheap, mechanical consolidation work from the audit while the test suite can still catch regressions.

The larger refactors, such as splitting `api.py`, adding `Feature` hooks and breaking up `features/lxmf.py`, are deferred to 0.2.0 (see [Deferred to 0.2.0](#deferred-to-020)).

## Ground rules for a patch release

Every change below must keep these intact:

- **Formats unchanged:** the wire protocol, DAG/CID encoding, archive format, sealed-file format, and on-disk state files (`*.json`, blocks, keys) are read and written exactly as in 0.1.1.
- **CLI and config unchanged:** no command, flag or config key is removed, renamed or reinterpreted.
- **HTTP API unchanged, with one exception:** the `seal_name` tightening in [F1](#f1--reject-non-boolean-seal_name-on-post-apiadd). It only affects requests that misbehave today.
- **Refactors are mechanical:** each one lands in its own PR and is covered by the existing tests.

## 2. CI guardrails

### C1 · Lint job

The code already contains `# noqa: BLE001` and `# noqa: E402` comments, which are ruff/flake8 rule codes, so ruff is the natural fit.

**Supply chain:** keep the existing hash-locking discipline:
- Add `ruff` to `BUILD_TOOLS` in `packaging/update-lock.py:54` and regenerate `build-tools.lock`.
- Add `ruff` to the names asserted by `test_build_locks` (`tests/test_packaging.py:162`).

**Configuration** in `pyproject.toml`. Start with rules that only flag real defects, so the first pass is fixes, not reformatting:

```toml
[tool.ruff]
target-version = "py311"
extend-exclude = ["packaging/flatpak"]

[tool.ruff.lint]
select = ["F", "E9", "B006", "B008", "B904"]   # pyflakes, syntax errors, mutable/call defaults, raise-from
```

**Job** in `.github/workflows/tests.yml`, running on `ubuntu-latest` with Python 3.12:

```yaml
lint:
  runs-on: ubuntu-latest
  steps:
    - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262  # v4
      with: { persist-credentials: false }
    - uses: actions/setup-python@a26af69be951a213d495a4c3e4e4022e16d87065  # v5
      with: { python-version: "3.12" }
    - run: python -m pip install --require-hashes --only-binary=:all: -r packaging/build-tools.lock
    - run: ruff check .
    - name: No merge-conflict markers
      run: "! git grep -nE '^(<<<<<<<|>>>>>>>)( |$)|^=======$' -- . ':!*.lock'"
```

Fix everything the first run reports in the same PR. K3 lists the dead code it is expected to find. Formatting (`ruff format`) and type-checking (mypy) stay out of 0.1.2: both would produce a large diff and belong in their own release.

### C2 · Gate releases on the tests

Today, `release.yml:215` makes the `release` job depend only on the build jobs, so a tag publishes even if the unit or E2E suite would fail. To fix this:

1. Make `tests.yml` reusable by adding `workflow_call:` to its `on:` triggers.
2. In `release.yml`, add a job `tests: { uses: ./.github/workflows/tests.yml }` and add `tests` to the `release` job's `needs`.

The packaging smoke tests then also run for every release, which means the duplicated sdist/wheel checks in `release.yml` can be removed (audit T-M5).

### C3 · Python 3.14

- Add `"3.14"` to the matrix in `tests.yml` and to `BUILD_PYTHONS` in `update-lock.py:60`, then regenerate the locks.
- Add the `Programming Language :: Python :: 3.14` classifier if `pyproject.toml` lists versions.
- **Condition:** this depends on every locked dependency publishing 3.14 wheels (`cryptography` ships abi3 wheels, and `cffi` ≥ 2.0 has cp314). If the lock can't be regenerated cleanly, leave 3.14 for 0.1.3 rather than relaxing `--only-binary`.

## 3. Dependency safety

### D1 · Upper version bounds

```toml
dependencies = ["rns>=1.5.6,<1.6", "lxmf>=1.2.0,<1.3"]
```

- **Why:** rnfs patches and reads RNS/LXMF internals in about 15 places (audit X1). An unbounded `pip install rnfs` should not pick up a release nobody has tested.
- **Caveat:** RNS does not follow strict semver; internals have changed in point releases. That is why the cap alone isn't enough and D2 is the real protection.
- **Other dependency copies:** apply the same bounds to `requirements.txt`, or delete it. It is the fifth copy of the dependency list (T-L1), and the README's "From source" can use `pip install -e .`. See Q3.
- **Lock test:** the lock test only parses package names (`tests/test_packaging.py:150`), so ranges need no test change.

### D2 · Compatibility test for RNS and LXMF internals

Add `tests/test_rns_compat.py`. It imports the *installed* RNS and LXMF and asserts that every private attribute, method and data layout rnfs depends on is present. Collect them into one documented list at the top of the test:

| rnfs code | RNS/LXMF surface |
|---|---|
| `network/guards.py:46-66` | `ResourceAdvertisement` fields `t d u l i q p` (after `unpack`), `Link.pending_requests`, `Resource.accept`/`reject` |
| `network/server.py:684-705` | `Link.register_outgoing_resource`, `Link.outgoing_resources` |
| `network/links.py:502` | `Link.incoming_resources` |
| `node.py:214`, `server.py:360` | `Resource.AUTO_COMPRESS_MAX_SIZE` |
| `node.py:396-411`, `names.py:175-179`, `features/peers.py:133` | `Identity.known_destinations` entry layout |
| `features/keepers.py:548` | `Transport.get_cached_packet` |
| `node_content.py:63-67` | `Identity.recall(..., _no_use=...)` keyword |
| `features/lxmf.py:1576-1633,1712,1777,1637` | `LXMRouter.get_announce_app_data`, `delivery_resource_transfer_began`, `request_messages_from_propagation_node`, `propagation_transfer_state`, `PR_*` constants, `outbound_propagation_link`, `delivery_destinations` |

**For the advertisement fields**, prefer a real round trip: pack an advertisement the way RNS does and `unpack` it. A simple `hasattr` on the class is not enough, because the fields are set per instance.

Each failing assertion should name the rnfs module that needs updating.

**Why:** a dependency bump, whether Dependabot, D4 or a user's own environment, then fails CI with a precise message rather than at runtime. The full `rns_compat.py` module that centralises the patches (audit X1) is deferred to 0.2.0. This test is the cheap half of that work, and it also produces the inventory the module will need.

### D3 · Make an RNS incompatibility visible at runtime

`guards.refusal()` returns `"malformed sizes"` when `adv.t`/`adv.d` are missing, so a renamed field in RNS would silently reject every incoming Resource, LXMF's included.

**Proposed change:**
- If the attributes are *absent*, as opposed to present but invalid, log once at `LOG_ERROR`:
  > `this RNS version (x.y.z) isn't supported by rnfs 0.1.2: incoming Resources are being refused`
- Keep failing closed. The guard exists to stop oversized allocations, and failing open would undo that.

This is a change to logging only. Add a test that feeds an advertisement object without `t`/`d` and asserts on both the refusal and the single log line.

### D4 · Bump the lock to rns 1.5.7

RNS 1.5.7 is on PyPI; the lock pins 1.5.6. Once D2 passes against 1.5.7, regenerate with `python3 -I packaging/update-lock.py rns==1.5.7 lxmf==1.2.0` and `python3 packaging/flatpak/generate-sources.py`, and run the full CI matrix.

This is optional for 0.1.2. Pick it up only if the RNS 1.5.7 changelog includes fixes rnfs users need.

## 4. Fixes

### F1 · Reject a non-boolean `seal_name` on `POST /api/add`

**Bug:** `node_content.add_options` (`node_content.py:231-233`) applies `parse_bool` only to values that are *already* booleans. Any other value passes through unchanged, so `POST /api/add {"seal_name": "false"}` reaches `add_path(seal_name="false")`, where the string counts as true. The failure is safe (the name is sealed anyway), but it is wrong.

The parameter means two different things:

| Endpoint | `seal_name` means | Type |
|---|---|---|
| `POST /api/add` (JSON body) | whether to seal the file's name | `bool` |
| `POST /api/add/stream` (query) | the name to seal inside | `str` |

**Change:**
- Pass the endpoint kind into `add_options`, e.g. `add_options(value, stream=False)`.
- For the JSON endpoint, accept only a JSON boolean, and raise `ValueError("seal_name must be true or false")` otherwise; the API turns that into a 400.
- Leave the stream endpoint unchanged.
- The CLI (`cli.add_options`, `cli.py:362-364`) already sends `False` or a name string correctly, so it is unaffected.
- Add API tests for `true`, `false`, `"false"` (expect 400) and `1` (expect 400).

Renaming the parameters to `seal_name: bool` and `sealed_name: str` is the clean fix, but it changes the API, so it is deferred to 0.2.0.

### F2 · `fsutil.write_atomic`

`design.md` promises that state is written "atomically and durably". Three of the seven copies of the atomic-write logic don't fully keep that promise:

| Writer | fsync file | fsync dir | Unique temp | Notes |
|---|---|---|---|---|
| `content/storage.py:81-97` `write_json` | ✓ | ✓ | ✓ | the reference behaviour |
| `names.py:747-762` `_write_atomic` | ✓ | ✗ | ✗ (`path + ".tmp"`) | `names.json` and name keys |
| `cli.py:56-69` `write_token` | ✗ | ✗ | ✓ | `O_EXCL \| NOFOLLOW`, mode 0600 |
| `network/identity.py:45-65`, `dht/providers.py:346-360`, `features/lxmf.py:424-444` | ✓ | varies | ✓ | copies of `write_json` |

**Proposed helper** in `rnfs/fsutil.py`:

```python
def write_atomic(path: str, data: bytes, *, mode: int = 0o644, durable: bool = True) -> None:
    """Replace path with data: a new temp file in the same directory (O_EXCL, O_NOFOLLOW where available,
    created with mode), written and fsynced, renamed over path (retried on Windows), then the directory
    synced if durable. On any failure the temp file is removed and path is left as it was."""
```

**Migration**, one commit each:
1. `names._write_atomic` → `write_atomic`. It gains the directory sync and a unique temp name.
2. `cli.write_token` → `write_atomic(path, token, mode=0o600)`. It gains the fsync and keeps the 0600 and no-follow guarantees.
3. `storage.write_json` → `json.dumps` followed by `write_atomic`. Add an `ensure_ascii` parameter so `lxmf.MessageLog` can drop its own copy.
4. `identity` and `providers` → `write_atomic`.

**Leave `blockstore.put` alone.** It is the hot path, has its own partial-file prefix and startup cleanup, and is already correct.

**Tests:** unit tests for `write_atomic` covering mode, replacing an existing file, refusing to follow a symlinked temp, and cleanup after an exception mid-write. CI's three-OS matrix covers the Windows `replace` retry.

**Risk:** Medium, because these paths write keys and tokens. Mitigations: one PR per call site, each with the existing tests for that file. File contents and names are unchanged, so no state migration is needed.

### F3 · `install.sh` installs the latest release

`install.sh:35` installs `archive/refs/heads/main.zip`, so the README's `curl … | sh` one-liner installs unreleased code, and `--update` "re-installs from the latest main branch".

**Change:**
- **Default:** resolve the latest release by following the `https://github.com/afit21/rnfs/releases/latest` redirect with the script's existing Python downloader (`install.sh:261-267`). This uses no GitHub API and so has no rate limit. Take the tag from the final URL and install `archive/refs/tags/<tag>.zip`.
- **`--main`:** a new flag that keeps the old behaviour.
- **`RNFS_SOURCE`:** still overrides both. CI uses it, so the packaging smoke test is unaffected.
- **Docs:** update the usage text (`install.sh:4-13`) and the README install section.

**Compatibility constraint:** the `install.sh` on `main` will now install trees from older tags. It must keep working with the 0.1.1+ layout (`packaging/requirements.lock`, `packaging/build-backend.lock`), which is already true. Add a comment saying so.

**Risk:** Medium, because the installer is user-facing. The `--update` flow should be checked by hand on Linux and macOS before tagging.

### K1 · Shared feature helpers

Create `rnfs/features/_common.py`. It replaces the copies of three helpers in five feature modules:

- **`printable`:** delete the `_printable` copies in `contacts.py:322`, `follow.py:339`, `peers.py:237` and `lxmf.py:111`, and use `fsutil.printable`. Their output is identical for control characters (`repr(c)[1:-1]` versus `unicode_escape`).

It replaces the five `_feature` copies and the inlined lookup in `peers.py:159`. `lxmf`'s copy (`lxmf.py:1332`) lets the `KeyError` from `node.feature()` escape. In a real daemon this can't happen: a feature's routes exist only while it is loaded. It only matters for nodes without the feature, such as `RnfsNode.offline()` and test fakes, so it is a consistency fix, not a user-visible change.

### Audit items examined and dropped

Checking against the code showed that these need no change:

- **"follow doesn't save on stop"** (audit F-M4): `follow` writes its state on every change (`follow.py:131,148,224`), so there is nothing unsaved at shutdown.
- **"`KeeperStore.save` re-marks dirty without the lock"** (F-M3): saves are serialised by `_save_lock`, and setting `dirty = True` after a failed write races only with other code setting it to `True`. It is benign.
- **"keepers `stop()` doesn't join its loop"**: the loop's `save()` and `stop()`'s `save()` are serialised by the same `_save_lock`, so there is no torn write. Joining would only tidy shutdown logging; it is left for the shared `BackgroundLoop` helper in 0.2.0.
